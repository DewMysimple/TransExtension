# 当前约束

## 结构与文档

- 根 `README.md` 和 `AGENTS.md` 管理全仓；两个插件继续保留各自的 `README.md`，并各有一个局部 `AGENTS.md`。
- 工程记忆只在根目录维护一套；受管页面必须用 `project` 标识归属。
- 原始代码、配置、插件 README、测试和来源元数据优先于记忆页；发现冲突时先核对事实来源。

## 产品与隐私

- 两个插件必须离线翻译固定界面，不得在运行时下载脚本、词库或调用翻译 API。
- 对用户生成内容采取保守保护策略；无法确定是固定 UI 时保留英文。
- 浏览器权限保持目标域和现有最小权限集合；扩大权限须先解释并确认。

## 质量与发布

- 使用 Node.js 22+；单插件修改至少运行其 `npm test`，跨插件改动运行两者测试。
- `npm run verify` 的 24 小时来源时效是来源刷新/发布门槛；无关任务不为通过门槛而擅自更新上游。
- 更新来源或发布按 `update:sources` → `test` → `verify` → `package` 执行，并审查生成 diff 与许可证。
- 插件行为和人工验收要求以各自 README 与局部 AGENTS 为准。

## 对话与 Git

- 完整对话产生仓库修改后，结束前必须执行记忆同步、相关验证、提交并推送到 `origin`；纯问答或只读检查不创建空提交。
- 不提交 `node_modules/`、`dist/`、临时报告、密钥或本机私有配置。
- 不用破坏性 Git 命令清理或覆盖用户修改。
