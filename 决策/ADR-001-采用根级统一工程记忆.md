# ADR-001｜采用根级统一工程记忆

## 状态

`active`

## 背景

仓库包含两个目标站点、产品边界和发布产物不同的翻译插件，同时需要共享工程规则、跨插件历史和统一导航。若在每个插件复制一套记忆，会产生重复事实、索引分裂和同步成本。

## 决策

- `当前状态/`、`决策/`、`知识/`、`日志/`、`模板/` 和检查工具只维护在仓库根。
- 根 `AGENTS.md` 作为共享治理与记忆 Schema；两个插件各自增加局部 `AGENTS.md`，只补充站点特有规则。
- 每个受管页面以 `project` 标记主归属；跨插件内容使用 `trans-extension`，并通过 `affected_projects` 列出实际影响。
- 两个插件现有 README 继续作为各自用户与开发文档，不被根 README 替代。

## 理由

- 新会话可从一个小型启动记忆包了解整个仓库。
- 公共决策和工作历史只有一个权威版本。
- 局部 AGENTS 仍能精确保护不同网站的用户内容与发布流程。
- Front Matter 和单一 MOC 可以按项目筛选，无需复制目录。

## 影响

- 正面：治理一致、可审计、跨插件检索简单、文档职责清晰。
- 代价：修改子插件后还需回到根目录同步日志和索引。

## 验证方式

运行 `python 工具/memory_lint.py check`，确认所有受管页面具有合法项目归属、链接完整且 active 主题无冲突；检查插件目录中不存在第二套记忆树。
