# 工程记忆项目归属

## 一句话结论

全仓只维护一套根级工程记忆；每个受管页面通过必填 `project` 和可选 `affected_projects` 明确主归属与影响范围。

## 允许值

| 值 | 使用条件 |
| --- | --- |
| `trans-extension` | 根治理、共享规范、仓库级状态，或同时影响多个插件的任务 |
| `figma-zh-ui` | 只属于或只修改 Figma 插件 |
| `github-zh-ui` | 只属于或只修改 GitHub 插件 |

## 规则

- `project` 必须是上表中的一个标量值。
- 单插件页面使用对应插件 ID，`affected_projects: []`。
- 跨插件页面或任务使用 `project: trans-extension`，并只在 `affected_projects` 列出实际受影响的插件。
- 根治理页面不需要受影响插件时使用 `project: trans-extension` 和空列表。
- `affected_projects` 不得重复主 `project`、不得重复自身、不得包含未知 ID。
- `topic` 使用稳定的 kebab-case，并带项目语义，例如 `figma-zh-ui-module`。
- active 状态/决策的唯一性按 `type + project + topic` 检查。

## 示例

```yaml
project: figma-zh-ui
affected_projects: []
```

```yaml
project: trans-extension
affected_projects: [figma-zh-ui, github-zh-ui]
```

日志按项目检索时先查看 `日志/MOC_工作日志.md` 的“项目”和“影响项目”列，不创建插件专属日志目录。
