# 完整对话交付闭环

## 适用条件

一次完整对话只要在仓库内产生文件修改，就执行本流程。纯解释、只读诊断或状态查询没有文件变化时不制造空提交。

## 步骤

1. 完成任务范围内的实现或文档修改。
2. 按 [[知识/流程/开发验证与发布|开发验证与发布]] 选择测试和检查。
3. 执行记忆同步：创建日志、沉淀已确认长期结论、刷新 MOC、运行记忆 lint。
4. 检查 `git status` 和 diff，排除秘密、依赖目录、构建产物及无关修改。
5. 以一个语义清晰的提交记录本轮相关变化。
6. 推送当前分支到 `origin`；首次推送建立上游跟踪。
7. 确认本地 HEAD 与远程对应分支一致，再在最终答复报告提交与验证结果。

## 异常处理

- 测试存在与本轮无关的已知失败：记录准确失败条件和证据，不擅自扩大任务修复。
- 推送认证或网络失败：保留本地提交并明确报告阻塞，不声称远程已更新。
- 远程已有冲突历史：先读取并安全整合，不使用强制推送覆盖未知提交。
