# 开发验证与发布

## 按影响范围选择验证

| 修改范围 | 最低自动验证 | 额外要求 |
| --- | --- | --- |
| 根文档或工程记忆 | `python wiki_memory/工具/memory_lint.py check` | 检查 Markdown 链接与 Git diff |
| 单个插件源码/配置 | 该插件 `npm test` | 按局部 AGENTS 判断是否运行 verify/人工验收 |
| 跨插件公共规则 | 两个插件 `npm test` | 记忆 lint 与全仓 diff 检查 |
| 来源更新或发布 | `update:sources` → `test` → `verify` → `package` | 审查来源、词库、许可证和产物，并做浏览器验收 |

## 常规开发

1. 读取根与目标插件的 AGENTS、README、package 和 manifest。
2. 首次或锁文件变化后使用 `npm ci`。
3. 只修改任务范围内的源码、配置、测试与文档。
4. 运行目标插件 `npm test`。
5. 权限、离线保证、来源或交付结构相关修改再运行 `npm run verify`。
6. DOM 选择器、动态导航、用户内容排除或恢复逻辑改变时，依子 README 做人工冒烟验收。

## 来源更新与发布

只有任务明确涉及更新词库或发布时，才运行：

```powershell
npm run update:sources
npm test
npm run verify
npm run package
```

更新脚本访问上游并改写生成文件；`verify` 将来源元数据限制为 24 小时内。若普通任务仅因元数据过期导致验证失败，应记录限制并保留上游固定版本，而不是为了“全绿”引入无关词库变化。

## 验收重点

- 权限仍为目标域和最小权限集合。
- 运行时没有远程网络请求。
- 用户内容未被翻译或写入审计。
- 关闭扩展后译文恢复为英文。
- README、版本号、许可证、第三方声明和包内文件与实际行为一致。
