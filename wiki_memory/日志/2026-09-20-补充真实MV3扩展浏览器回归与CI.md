# 2026-09-20｜补充真实 MV3 扩展浏览器回归与 CI

- 状态：实际扩展自动验证完成；真实登录页面覆盖仍未验收。
- 目标：继续用户的双插件可维护性目标，补上此前 DOM 合成测试使用 Chrome API 替身、无法证明扩展模块接通的缺口。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]。

## 已确认的决策

- 继续既有离线、最小权限、独立安装/打包和用户内容保护约束。
- 不把扩展在合成页面的运行结果当作登录真实站点全覆盖证明。

## 检查与操作

- 重新核对仓库：上一提交为 `eb2ef09`，开始时工作区干净。
- 使用公共 GitHub API 核实上一提交的 [CI 运行](https://github.com/DewMysimple/TransExtension/actions/runs/35520878491) 已成功完成，Windows 和 Ubuntu 两个任务及全部步骤通过；没有读取凭据。
- 核对 [Playwright 扩展测试说明](https://playwright.dev/docs/chrome-extensions)：当前 Chrome/Edge 不支持所需自动侧载参数，采用独立测试 Chromium。
- 根目录引入精确版本 `@playwright/test` 1.63.0 和锁文件，只用于开发验证；不更改两个扩展的清单、权限、运行源码或生成词库。
- 测试使用临时持久上下文加载原始 manifest；目标域响应替换为合成 fixture，其他外部请求被阻断，允许浏览器加载本地扩展文件。没有读取或修改日常浏览器配置。

## 文件变更

- `package.json`、`package-lock.json`：固定开发依赖和 `npm run test:browser` 入口。
- `playwright.config.mjs`：单 worker、无重试、明确超时和输出目录。
- `tests/browser/extensions.spec.mjs`：两个扩展共享 4 个端到端流程，验证真实 service worker、隔离内容脚本、目标域匹配、保护区域、异步控件、路由、动态编辑保护、popup 设置同步、runtime 消息、storage、报告导出/清空与取消审计。
- `.github/workflows/checks.yml`：现有 Windows/Linux 检查安装根锁定依赖，新增独立 Ubuntu 浏览器任务。
- `.gitignore`：排除浏览器报告和测试结果目录。
- 根 README、双插件 README 与 `docs/maintenance.md`：根安装步骤、浏览器命令、测试边界和人工验收说明。

## 测试与验证

- 本机测试 Chromium 153.0.8010.12：`npm run test:browser` 4/4 通过。
- 真实弹窗页面读取后台数据、切换设置、下载审计 JSON 和清空报告成功，未使用扩展 API 替身。
- `npm ci` 可按根锁文件重新安装。
- `npm run check` 通过：共同门禁 32、Figma 43、GitHub 31，共 106 项；双方离线静态验证和记忆检查通过。
- `git diff --check` 通过。本轮未刷新来源，上一轮记录的 24 小时发布门槛限制仍然存在。
- 登录后的 Figma 文件浏览器/编辑器等真实 DOM、工具栏 popup 定位和 activeTab 用户手势行为仍不在这组自动测试的证明范围内。

## 待确认长期记忆

- 后续涉及扩展加载、后台、消息、设置、popup、审计导出或清空的修改，可用真实 MV3 浏览器回归作为额外质量门禁。
- 根目录现在具有开发测试依赖；两个扩展的安装和运行包依然独立。原始配置和 README 是事实来源，本轮不另新增 ADR。

## 问题、结果与下一步

- 自动验证从纯 DOM 层扩展到实际浏览器扩展集成层，提高了后续修改的回归发现能力。
- 剩余关键证据仍是用户安装目录及实际页面漏译样本/验收结果；不能用新增合成测试数量替代实际覆盖率。
- 本轮文件与日志提交推送后，核实新增 CI 浏览器任务；具体提交和远端结果在交付答复记录。
