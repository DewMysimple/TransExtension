# ADR-002｜完整对话修改必须提交并推送

## 状态

`active`

## 背景

用户要求每次完整对话产生的修改都进入可追溯的远程 Git 历史，避免本地工作完成但未交付或下一会话缺少上下文。

## 决策

只要一次完整对话产生仓库文件修改，Agent 必须在结束前完成相关验证、工程记忆同步、Git 提交，并推送当前分支到 `origin`。没有文件修改的纯问答和只读检查不创建空提交。

## 理由

- 远程提交成为每轮交付的恢复点。
- 工作日志、代码和决策在同一提交中保持一致。
- 后续会话可以同时依靠记忆与 Git 历史审计变化。

## 影响

- 正面：修改不会静默滞留在本地，协作状态清晰。
- 代价：每轮结束必须预留验证、检查 diff、提交和推送时间；认证或网络异常会成为明确阻塞。

## 验证方式

结束前确认工作区无本轮遗漏修改、`git log -1` 包含本轮提交，并验证本地当前分支与 `origin` 对应分支一致。失败时在最终答复中如实报告，不声称已经推送。
